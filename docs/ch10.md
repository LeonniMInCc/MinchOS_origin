# 第 10 章　Shell：让系统能交互

> 对应 tag `v0.10`。本章代码：`git diff v0.9..v0.10`
>

## 10.1 shell 其实没剩多少活要干

一个 shell 本质上只做三件事，而这三件事前两周刚好都做完了：

| 做什么 | 靠什么 | 哪一周做的 |
|---|---|---|
| 读一行命令 | `sys_read` | 第 10 周（本章） |
| 开一个新进程去执行 | `fork` + `exec` | 第 9 周 |
| 等它结束、拿到退出码 | `waitpid` | 第 9 周 |

所以这一章真正的新东西只有"读输入"。剩下的是把已有的积木拼起来。

有一点值得强调：**shell 不是内核的一部分**，它就是一个普通的用户程序，
没有任何特权。这是 Unix 设计里最重要的观念之一 —— 你完全可以写一个自己的
换掉它。看 [`user_shell.rs`](../user/src/bin/user_shell.rs) 的
`#![no_std] #![no_main]` 就知道，它和 `00hello_world` 是同一类东西。

## 10.2 `File` trait：现在抽象，后面省事

第 10 周只有两种"文件"：标准输入和标准输出，都是串口。为它们定义一个 trait
看起来像是过度设计 —— 直接在 `sys_read` / `sys_write` 里
`if fd == 0 {...} else {...}` 也能跑。

但这个抽象是后面两章的地基：

- **第 11 周**：管道也是"文件"。`ls | wc` 靠的就是把 `stdout` 换成管道
- **第 13 周**：磁盘上的真实文件

有了 trait，那两章只要多写一个实现，`sys_read` / `sys_write` 一行都不用改。
这就是 Unix "一切皆文件"那句话的技术含义。

```rust
pub trait File: Send + Sync {
    fn readable(&self) -> bool;
    fn writable(&self) -> bool;
    fn read(&self, buf: UserBuffer) -> Option<usize>;
    fn write(&self, buf: UserBuffer) -> Option<usize>;
}
```

注意是 `&self` 而不是 `&mut self`：一个打开的文件可能被好几个进程同时持有
（`fork` 复制文件描述符表，但**共享底下的文件对象**），所以内部可变性
要由实现自己处理。

## 10.3 文件描述符表

PCB 里多了一张表：

```rust
pub fd_table: Vec<Option<Arc<dyn File>>>,
```

下标就是 fd，`None` 表示槽位空着。前三个按惯例是 0=stdin、1=stdout、2=stderr。

`fork` 时**复制这张表，但表里的 `Arc` 指向同一批文件对象**。这正是 Unix 的
语义：父子往同一个 stdout 里写，内容会交错而不是各写各的。运行日志里能直接
看到这个效果 —— `11forktest` 的父子两行输出偶尔会插在一起。

## 10.4 "阻塞读"是自己实现的

SBI 的 `console_getchar` **不阻塞**：固件只是看一眼串口寄存器，有就给，
没有就返回 -1。所以"等一个字符"这件事必须由内核自己做：

```rust
let ch = loop {
    match console_getchar() {
        Some(c) => break c,
        None => suspend_current_and_run_next(),   // 让别人先跑
    }
};
```

这是**忙等**：没有输入时，这个进程每被调度到一次就白跑一次。
真正该做的是把进程挂进等待队列，等串口中断来了再唤醒 —— 那需要
外部中断（PLIC）和等待队列，是第 14 章的事。

在那之前忙等是可接受的：调度器总会把 CPU 分给别的进程，
只是浪费掉本该属于这个进程的那些时间片。

这也解释了**为什么 shell 必须等到有了进程调度才能做**：
没有别的进程可跑的话，"等输入"就只能空转烧 CPU。

## 10.5 一个必须绕开的死锁

这是本章最容易踩的坑。看下面这段**错误**的写法：

```rust
let inner = task.inner_exclusive_access();
let file = inner.fd_table[fd].as_ref().unwrap();
file.read(buf)   // ← inner 还借着！
```

`Stdin::read` 在没有输入时会调 `suspend_current_and_run_next()`，
而那个函数要访问**同一个进程控制块**。于是 `RefCell` 发现重复借用，
当场 panic。

正确做法是先把 `Arc` 克隆出来、释放借用，再去 read：

```rust
fn fd_to_file(fd: usize) -> Option<Arc<dyn File>> {
    let task = current_task()?;
    let inner = task.inner_exclusive_access();
    inner.fd_table.get(fd)?.clone()
    // inner 在这里析构，借用释放
}
```

> **一个"可能让出 CPU 的调用"绝不能握着锁进行。**
>
> 这是所有内核里都成立的规矩，只是在 C 写的内核里它不会当场把你拦下来 ——
> 那边的表现是真正的死锁或者数据损坏，可能几个月后才暴露。
> 第 2 章选 `RefCell` 而不是裸 `UnsafeCell` 的价值，在这里又兑现了一次。

## 10.6 shell 的行编辑

串口是裸设备，**没有回显、没有行缓冲**。所以：

- 敲的每个字符都要 shell 自己打出来，否则屏幕上什么都不会显示
- 退格要手动模拟：`\x08` 光标左移、打个空格盖掉、再 `\x08` 移回来

```rust
BS | DEL => {
    if line.pop() {
        print!("{}", BS as char);
        print!(" ");
        print!("{}", BS as char);
    }
}
```

顺带一提，退格键在大多数终端上发的是 `DEL`(0x7f) 而不是 `BS`(0x08)，
两个都要认。

命令行用的是固定大小的 `[u8; 256]` 而不是 `String` —— 用户库还没有堆
分配器。对教学 shell 来说 256 字节绰绰有余，省掉了在用户态再实现一个
分配器的麻烦。

## 10.7 一次完整的会话

```
CCNUOS shell —— 输入程序名回车执行，输入 help 看有哪些程序，exit 退出
ccnuos> 00hello_world
你好，我是跑在 U 态的第一个用户程序。
...
[INFO ] 进程 2 正常退出，退出码 0
ccnuos> 11forktest
  [fork] 我是 pid 2，MARK @ 0x13000 = 0xf00d
  [fork] 父进程 pid=2，fork 返回 3（子进程的 PID）
  ...
ccnuos> 09bad_address
我要往地址 0x0 写一个字节。
[ERROR] 用户程序访存出错：StorePageFault，地址 0x0 —— 杀掉，换下一个
[2] 退出码 -1
ccnuos> nosuchprogram
ccnuos: 找不到命令 "nosuchprogram"
[2] 退出码 127
ccnuos> exit
再见。
[INFO ] 页帧核对：67 页，与用户态启动前完全一致，无泄漏
```

几个细节值得看：

- **进程号一直是 2。** shell 是 pid 1，每条命令 fork 出的子进程用完就被
  回收，PID 还回分配器，下一条命令又拿到同一个号
- **作恶的程序被杀掉后，shell 毫发无损**，还能继续接受命令
- **退出码是 127**，和大多数 shell 对 "command not found" 的约定一致
- **零泄漏**：一整轮交互下来，页帧数和用户态启动前完全一致

## 10.8 一个真实的限制：没有输入缓冲

做自动化演示时发现：如果把一整个脚本一次性喂给 QEMU 的串口，
命令会**缺字母** —— `help` 变成了 `elp`。

根因不是 QEMU 的问题，是我们自己的：**CCNUOS 没有输入缓冲**。
SBI 只提供"看一眼串口有没有字符"的非阻塞接口，内核靠轮询取。
两次轮询之间到达的字符如果超出了串口硬件那点 FIFO，就丢了。

真人打字每秒几个字符，轮询完全跟得上，所以交互使用时察觉不到。
但**粘贴一段长命令同样会丢字符** —— 这是个真实的缺陷，不是测试工具的问题。

根治要靠外部中断：串口收到字符时产生 PLIC 中断，内核在中断处理程序里
把它存进一个环形缓冲区，`read` 从缓冲区取。那需要 PLIC 驱动和等待队列，
是第 14 章的事。

在那之前，`tools/capture.sh` 做了个务实的变通：按行喂、每行之间留间隔。
**把工具的变通和内核的缺陷分开记录**，免得以后误以为问题已经解决了。

## 10.9 练习

1. **去掉 `fd_to_file` 里的 `.clone()`**，直接握着借用去 `read`，
   看 `RefCell` 怎么把你拦下来。这是 10.5 节那个坑的复现。
2. **给 shell 加历史记录**：上下方向键翻之前的命令。
   方向键是转义序列（`ESC [ A`），需要一个小状态机。
3. **加一个 `sys_dup`**，然后在 shell 里实现 `>` 重定向 ——
   不过输出目标还只能是 stdout，真正有用要等第 13 章的文件系统。
4. **让 shell 支持后台执行**（命令末尾加 `&`）：fork 之后不 `waitpid`，
   直接回到提示符。想清楚这些子进程最后由谁回收。
5. **测一测输入丢失**：写个脚本一次性喂 200 个字符，统计实际收到多少。
   然后把 `Stdin::read` 改成一次尝试读多个字符，看有没有改善。
